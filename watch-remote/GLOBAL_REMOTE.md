# TGR1 · 受控全局输入 / 2026-09-28

仅针对已审计的 Strix OS 1.0.4.12 AP ABI。2026-09-29 公开的是源码研究模块，不是完整固件发布。私用 TGR1 有用户反馈刷入完成，但随后反馈“翻页翻不了”，原因及逐页输入效果尚未闭环；不得称为全局遥控稳定可用。公开抽取版没有进行设备安装或刷写，没有自动安装/授权/刷写。

## 通信约束

使用现有已配对的 iPhone → 眼镜业务 15 通道。PB 外层固定为 sequence=1、type=127、长度 68 的字符串。字符串是 `TGR:` 或回执 `TGA:` 加 32 字节帧的小写十六进制，总计 74 字节。

原厂接收代码静态分析显示 type 127 不在其动作分支内；旧固件忽略该类型是静态结论，仍需实机确认不会干扰官方页面。新固件在既有 `LauncherThreadMsgHandler` hook 中先读取固定帧，再恰好一次调用原处理器，原始载荷仍按原规则释放。

| 字节偏移 | 请求 TGR1 | 回执 TGA1 |
|---|---|---|
| 0–3 | magic | magic |
| 4 | version 1 | version 1 |
| 5 | opcode | result |
| 6 | 0 | opcode |
| 7 | 0 | 0 |
| 8 | request ID / u32 | request ID |
| 12 | session / u32 | current session |
| 16 | sequence / u32 | accepted/consumed sequence |
| 20 | estimated eye tick ms / u32 | actual eye tick ms |
| 24 | random client ID / u32 | echoed client ID |
| 28 | CRC32 of bytes 0–27 | CRC32 of bytes 0–27 |

整数均 little-endian。opcode：0 HELLO、1 PREVIOUS、2 NEXT、3 PRESS、4 BACK、5 CLOSE。HELLO 的 session、sequence、tick 必须为零。不是加密协议；CRC 只查传输/格式错误，访问边界仍是原厂已配对通道与手机授权，不能称为独立安全认证。

会话租期 15 秒；手机每 6 秒尝试握手续租，眼镜时钟样本超过 12 秒不操作。握手往返大于 1.5 秒不采纳。动作眼镜时钟有效窗口为过去 1500 毫秒、未来 250 毫秒；眼镜最短间隔 350 毫秒，Watch 及手机分别限频。每次只有一个在途动作，手机 2 秒超时；不重传、不补队列。

结果 0=已分发、1=仅唤醒、2=策略阻止、3=过期/重复、4=会话不符、5=忙碌、6=格式错误、7=当前输入设备不可用。除“已分发/仅唤醒”外，不能当成执行成功；已分发也必须看镜片结果。

## 原厂分发适配

所有动作在 launcher 既有 UI 消息线程内执行。确认/返回构造与原厂 `rayneo_indev_keypad_proc` 一致的 28 字节事件（code 14、key 0x3a/0x3b），先经过原厂全局拦截器。若未消费，重新查询当前 keypad group 再分发，避免拦截后页面切换导致旧焦点指针。

旋钮模仿 `rayneo_wheel_read`：先给 raw-wheel 监听者 `{int32 x,y; uint64 time_us}`，再向原厂 encoder 输入缓冲送一个 detent。已有未消费 detent 时返回忙碌，不能覆盖。原厂方向字节影响 raw 符号；旧自定义页面和 stock 菜单可能采用不同方向约定，首次验收必须逐页确认。Watch 提供反转方向，但这不是跨页面正确性的证明。

没有劫持实体表冠按压；没有调用会阻塞或产生配对/重置行为的 `rayneo_sim_button`。允许的包是正向名单，但 launcher 内仍有子页面；不能据此宣称对所有危险子菜单自动识别。

控制器在 AP 首次有效协议帧时分配，后续从固定回调的 timer 找回，控制器存活至系统重启；一次固定大小请求加一个原厂 timer，没有每输入分配。遍历 timer 上限 512、输入设备上限 16；分配失败不注入、不假报成功。回执使用原有 send 的短帧生命周期约定，未新增文件或大缓存。

## 不改动的部分

- BTH、Recovery、引导、资源和其他非 AP 负载不变；AP MD5/长度及 OTA 清单/包 SHA 重新生成。
- 原有 14 项菜单，不新增菜单占位；全局遥控不是新眼镜 App。
- 不修改官方 App 可执行代码逻辑；沿用其传输实现和已有插件 hook。
- iOS 原有 OTA 默认锁定、独立授权、Mode 2、设备/清单/分片校验规则不弱化。

## 下一轮验收顺序

1. 在具备兼容原宿主、签名和已审核配套固件的测试环境中，先核对手机插件、Watch 屏幕布局、四个按钮、表冠“仅本机识别”；不要为了运行本源码而直接刷未知固件。
2. 手机 TGR1 固件页只下载校验；核对实际官方解压目录全部 15 项，不能拿离线报告代替。再次明确确认 TGR1 和电量后才允许刷写。
3. 刷后先确认正常首页、实体旋钮及原有 App；重启手机退出旧升级保护（必须已经完成更新），然后建立全局握手。
4. **先屏幕按钮**：醒屏/首页单步→四项菜单单步→确认进入→返回；再用表冠。每次一次，不连按。
5. 阅读、音乐、导航、番茄各自确认/返回及旋转方向，检查不重复触发、没有两页同时响应；有异常立即关闭手机遥控，保留日志。
6. 最后验收手势、息屏首次只唤醒、断开/重连不补发、退出 Watch 不再操作、OTA 保护拒绝。后台可达性另测。

只在每层获得真实证据后推进；未通过前不能发布为稳定版或把“固件回执”写成“镜片验收成功”。
