# Apple 提醒事项与日历同步

本页说明 Turbo IO V2 官方 App 扩展如何把眼镜待办与日程同步到 iOS 的 Apple 提醒事项和日历。

## 规则

- 眼镜待办只有在官方创建成功，并从完整列表中匹配到唯一官方编号后，才会创建对应的 Apple 提醒事项。
- 没有明确时间的待办只写入 iOS 当前默认可写提醒事项清单；不会为了同步而补造日期或时间。
- **待确认的产品口径**：带明确起止时间的日程是否还要创建独立 Apple 日历事件。当前 PR 草案暂按“日历事件 + 配对提醒事项”实现；这只是候选方案，不是已确认规则，确认前不应合并。
- 已有官方待办可以在“待办同步”页面由用户选择并确认一条 Apple 提醒事项的精确编号。重连、重启和写入失败使用本机编号状态去重和恢复；同名多条或只读清单不会被自动修改。
- 已关联事项优先用保存的 EventKit 本机编号读取；本机编号失效时，只允许用保存的外部标识在全部提醒事项中找到唯一、同标题的原事项后自动恢复。找不到、外部标识缺失或匹配不唯一时返回 `needs_relink`，暂停自动创建与完成，保留旧编号用于诊断；清单和标题不能单独证明身份。用户须在同步页明确选择候选事项，再确认精确编号，之后才能继续完成写入。重新关联时即使只有一条候选，也要求用户选择。若没有候选，需先在 Apple 提醒事项中准备正确事项，再回来选择。若眼镜完成消息缺少必要字段，仍可先重新关联，但不能在该步提交完成状态。
- 完成 Apple 提醒事项前需要明确确认。已关联的待办在 App 内确认时先更新 Apple，再向眼镜提交同编号状态；取消、权限不足或写入失败时保留可见状态。

## 数据与限制

官方编号、设备关联、待重试状态和 EventKit 标识保存在本机，用于关联与恢复。待办标题不会写入上传服务。旧版未能自动关联的事项可以由用户在同步页逐条关联；删除、网页端同步和历史事项的自动导入不属于此功能。[Apple EventKit 文档](https://developer.apple.com/documentation/eventkit/ekcalendaritem/calendaritemidentifier?language=objc)指出完整同步后本机编号可能失效；[外部标识文档](https://developer.apple.com/documentation/eventkit/ekcalendaritem/calendaritemexternalidentifier?language=objc)也说明它可能对应多份条目，因此恢复时要求唯一匹配。

直接通过官方语音流程完成 Apple 提醒事项的入口仍保持关闭，直到该流程能在眼镜上验收。用户可使用扩展提供的提醒事项操作工具或同步页面确认；工具不会完成雷鸟官方待办。

## 验收边界

仓库已有记录：合成数据测试覆盖编号解析、差分、去重、提醒事项关联、完成确认和错误状态；此前真机读回验证过两条新建无时间待办写入 Apple 提醒事项。本轮在两个构建版本的离线测试中补测了“删除旧事项后出现同名新事项”“跨清单同名”“外部标识无匹配”“外部标识重复”和正确原事项匹配，均未访问真实 EventKit 提醒事项。V2 与启用显示通道的 FOCUS-04 插件已在 Xcode 27.0 / iPhoneOS 27.0 SDK 下本地编译并临时签名；这是源码构建结果，不是已安装 IPA。本分支的完整测试与复现命令见下方最新变更记录。有时间日程的日历表示方式仍待确认；锁屏/断连恢复、权限失败和完成状态的完整真机验收也仍需补齐。编译、签名或本地测试结果不能替代 Apple 系统应用的读回。

## 变更记录

### 2026-09-25 · 初次加入

- **涉及模块**：`AppleCalendarSync`、`TodoProtocol`、`TodoCompletionLedger`、`TodoRuntime`、模型工具路由、V2 打包权限及构建脚本。
- **修改前后差异**：原扩展可以创建眼镜待办，但没有写入 Apple Reminders / Calendar 的自动关联。本次新增本机 EventKit 写入、无时间待办映射、编号差分去重、失败状态保留、同步页面和明确完成确认。定时日程创建独立日历事件目前只是候选实现。
- **原因与影响**：让用户可以在 iPhone 系统应用中管理 Turbo IO 新建的事项，同时避免不确定编号、同名项目或权限错误导致误建、误完成；将未确认的日历映射单独标为待决，避免误当成已定规则。
- **验证结果**：仓库记录了本地合成测试、arm64 构建/签名，以及两条无时间待办的 Apple 提醒事项读回；本轮未重跑这些验证。
- **未决项**：定时日程是否创建独立日历事件；锁屏/断连恢复、权限失败和完成状态的完整真机验收；直接官方语音完成入口仍关闭。

### 2026-09-28 · PR #30 审查修复：提醒事项恢复匹配

- **涉及模块**：V2 与 FOCUS-04 两份 `AppleCalendarSync`、离线测试和同步页提示。
- **修改前后差异**：原本机编号失效且外部标识无匹配时，完成路径可能按同标题、同清单或全局唯一同标题自动找到新事项并完成。现在只接受唯一的已保存外部标识；若无法确认身份，则记录 `needs_relink` 并阻止自动新建和完成。用户必须明确选中候选的精确编号并确认，单候选也需选择；重新关联成功后才清除停写状态。缺少眼镜完成消息字段时允许先关联，不开放完成操作。
- **原因与依据**：[Turbo1123 对 PR #30 的审查](https://github.com/Turbo1123/Turbo-IO/pull/30#pullrequestreview-5338884329)指出删除旧事项后同名新事项可能被误完成；Apple EventKit 的本机编号与外部标识文档说明了编号失效与外部标识重复的边界。
- **影响范围**：官方待办与 Apple 提醒事项的恢复、确认完成和重新关联流程；不改变定时日程候选映射。
- **验证结果**：`bash official-addon/test.sh` 通过，包含两份 `AppleCalendarSyncTests` 的合成恢复场景与跨进程完成状态测试；测试脚本中 FOCUS suite 前缀已与断言对齐，并在成功后清理临时 suite。`bash official-addon/build.sh embedded com.rayneo.venus.pub` 与 `TIO_DISPLAY_PHONE=1 TIO_IMAGE_RX_LAB=1 bash official-addon/focus-edition/build.sh embedded com.rayneo.venus.pub` 均完成 arm64 构建和本地 ad-hoc 签名。普通 FOCUS 构建不启用显示通道时仍有与本次恢复匹配无关的导航/诊断符号缺失；本轮验证范围是上述启用显示通道的 FOCUS 构建。没有访问或修改真实提醒事项，也没有安装 IPA。
- **未决项**：在本分支的真机 EventKit 上验证失效编号、用户重新关联、锁屏/断连和权限失败；定时日程是否额外创建日历事件仍需产品决定。
