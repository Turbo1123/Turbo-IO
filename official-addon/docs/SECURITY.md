# 源码发布与隐私边界

## 本目录不分发什么

不包含官方IPA、官方主程序、砸壳文件、厂商framework、预编译扩展、修改后的App、签名描述文件、证书私钥、维护者API Key、手机备份、设备ID、聊天记录、录音、私人知识库或真机截图。仓库其他目录原有的V1构建依赖保持其原通知与许可，本次未新增或替换这些二进制。

发布从独立干净克隆开始，只复制明确选择的源码文件；没有整体同步私人研究目录，也没有复制其Git历史或调试日志。

## 检查方式

- Gitleaks：发布副本与提交历史，输出100%脱敏。
- `node scripts/check-source.mjs`：检查硬编码Key模式、私人主目录、专有服务域名、临时隧道、二进制/媒体产物；截图按确切哈希逐张人工检查，不做目录整体豁免。
- Git提交清单：只允许本次源码、文档及已审查的无账号模拟器截图，构建结果不暂存。
- 与本机私用配置中的实际凭据做无回显比对，检查是否意外复制。检查报告不包含凭据或原始配置。

扫描降低风险，不是“永远不会泄漏”的保证。贡献者同样需要检查自己的改动与历史；不要因为文件在gitignore里就用`git add -f`上传。

## 使用者配置

- 模型/搜索Key在程序界面输入，存手机钥匙串；公开构建禁用IPA资源中的私用bootstrap自动导入。
- 个人资料与回答偏好默认全空，属于本机配置；会随自有模型请求发送，不能拿来存密码。
- 知识库令牌是独立凭据，拒绝重定向；更换连接地址需要重新输入令牌，不把旧令牌自动转给新地址。
- 本地生成的IPA即使没有API Key，也可能包含自己的签名、描述文件和设备授权信息。仅自己保管，不上传本仓库或issue。
- 来源资料、导出副本、查询结果均可能包含私人数据。报告问题时只提供最少必要的脱敏摘要。

## 漏洞与意外泄漏

不要在公开issue提交可用凭据、完整配置或私人文件。先撤销暴露的Key/令牌，再通过GitHub可用的私密渠道联系维护者。删除当前文件不等于清除历史；不要把未撤销凭据继续使用的风险转嫁给扫描工具。

本项目不修改官方登录、付费或数据权限检查，也不授予访问他人数据的权利。只用于自己有权操作的设备、软件与资料。
