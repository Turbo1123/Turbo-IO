# 用 Claude Code / Codex 接入 Turbo IO

**2026-10-19 路由更新：** iOS 1.0.7（230）使用 [APP107 专用目录](../official-addon/ios107-edition/README.md)，继承 NAVS3、沿用现有 TMG2，**OTA 已在 iPhone 17 Pro Max 实刷通过并开放**；需要自行准备合法的 1.0.7 未加密输入，按[专用刷机教程](../official-addon/ios107-edition/OTA.md)完成校验、单次授权与刷后收尾。1.0.6（218）使用 [NAVS3](../official-addon/navs3-edition/README.md)，其固定门禁不能移用。下方旧版说明仅作历史参考，不得通过改版本白名单假装兼容。

目标是把重复的环境检查、构建、合并和排错交给编程助手，让开发者主要完成账号、签名、设备确认和实测。**不是承诺一条提示词就能跨过所有安装限制，也不是成品 App 安装服务。** 仅限非商业学习研究。

## 先给助手三样东西

1. 本仓库：<https://github.com/Turbo1123/Turbo-IO>。
2. Android 使用 [雷鸟 AI Android 官方下载入口](https://rayneo.cn/commonPage/venus/appDownload/index_m.html)，不是 Turbo IO 安装包或固定旧版存档。**iOS 官方扩展可使用[明确列出的原厂解密输入](../official-apps/ios/README.md)，或自行准备有权使用的兼容副本。1.0.6（218）输入已去签名，对应 TMIG1；无插件，仍需自己合并与签名。** 不提供代砸壳或代签服务。商店安装仍不等于取得可合并的未加密 Runner.app，不能跳过版本与哈希校验。
3. [首页可复制的完整提示词](../README.md#让-claude-code--codex-帮你接入)，并选好自己的平台。不确定路线时让助手先解释五个选项，而不是同时搭建全部组件。

原生鸿蒙 HarmonyOS、iOS 独立 SDK 与仅 Web 预览不需要官方应用副本；鸿蒙按 [源码安装教程](../harmony-sdk/README.md) 自行编译签名。

在电脑端编程助手中打开自己的工作目录，允许其在任务范围内读取文件、执行构建命令。Codex 的本机项目使用方式可参考 [官方入门](https://learn.chatgpt.com/docs/quickstart)。Claude Code 使用项目目录中的同一份自然语言提示词即可，不依赖本项目专用云账号。若助手只能远端聊天，先让它生成清单，转到能访问开发电脑的环境继续；云端不能看到你的 USB 手机。

**不要把 API Key、签名密码、登录验证码当作“第三样东西”发进提示词。** 这些只在你自己的程序设置、本机凭据存储或交互式签名工具内输入。

## 五条路线，不混用

| 目标 | 助手先做 | 用户提供 / 确认 | 当前门槛 |
| --- | --- | --- | --- |
| Web 预览 | `node display-observer/server.mjs --no-proxy`，检查页面 | 一个可用端口和浏览器 | 不要误报为真实眼镜画面；不需要官方包、Key或手机 |
| 原生鸿蒙 | [鸿蒙教程](../harmony-sdk/README.md)，DevEco 打开 `harmony-sdk`，先跑测试和无维护者签名构建 | 自己的华为开发者签名、手机调试授权、各服务 Key | 不需要官方 APK/IPA；系统通知转发未实现，需要受限权限与用户授权；不提供 HAP |
| iOS 独立 SDK | [配置文档](CONFIGURATION.md)，`scripts/start.mjs --local` 或 `--device` | macOS/Xcode、自己的签名和服务配置 | 切换客户端时才先官方解绑、系统忽略，再重新配对 |
| iOS 官方扩展 | [扩展说明](../official-addon/README.md)，先测试与零密钥预览，再按条件本地合并 | 合法兼容未加密 `Runner.app`、个人证书/描述文件与设备授权 | 1.0.4（195）或1.0.2（67），对应UUID及thin arm64校验；普通商店加密IPA不能直接合并 |
| Android 官方扩展 | [Android教程](../android-addon/README.md)，检查JDK/SDK，运行build和package脚本 | 合法官方APK、自己的keystore、测试手机和服务配置 | 当前1.0.4（195）且精确SHA匹配；非Root设备已由用户实机验证可用 |

iOS / Android 官方扩展**不是第二个独立蓝牙客户端**，沿用宿主的配对和识别。不要看见首页V1的“先解绑”就把现有官方连接清掉。不要自动卸载正在使用的官方App；签名冲突可能需要另外的测试设备或恢复方案。

## 推荐的一次接入过程

### 1. 环境和版本预检

助手先报告选择的路线、当前源码提交、工具缺项、目标设备。已有项目先检查未提交改动，不覆盖或重置。

需要官方输入时，Android从上方页面自行获取，iOS使用用户另行自行准备的合法兼容未加密副本；保存原件并记录校验信息。**不要把页面“最新版”当作本项目“已适配版”。** 未知版本时给出实际版本和拒绝原因，等待兼容包或新的适配；不要更改SHA/UUID白名单来伪装兼容，不提供或执行解密绕过。

### 2. 在不影响手机的情况下先验证

- Web检查HTTP及页面样式；iOS可先构建无账号/无Key预览。
- Android设置自己的 `ANDROID_SDK_ROOT` 后运行 `bash android-addon/build.sh`，先通过原创代码测试；输入兼容时再本地合并。
- 构建缺SDK/工具时，按平台教程补全或列出缺项，不需要先重置眼镜。
- 不需要先为运行本项目把任何Key嵌入源码；合并生成物放在被忽略的本机目录，不能上传GitHub。

### 3. 签名、安装和连接

助手可以准备命令并检查产物；用户选择自己的证书/keystore、解锁设备并确认信任或调试授权。真正安装、重启、卸载或改绑定前确认设备与当前任务，保留可恢复的原件和个人资料。

Android非Root设备已有用户实机可用确认；但换签仍不能直接覆盖原厂签名，原高德配置也可能受签名影响，不保证所有证书与机型一致。iOS保留Bundle ID也不等于拥有原厂推送/钥匙串授权。具体处理以平台教程为准。

### 4. 自己填服务，先做最小测试

官方扩展保留官方ASR；先随机文字/短问答测试，再配置模型地址、模型ID与自己的Key，按需开启TinyFish和知识库。V1云语音另需自己的ASR设置，不与官方扩展混淆。

模型能回答后，再测试插话、收尾、文件分享和导航。眼镜显示由使用者实际确认，成功回执不能代替镜片检查。不要一开始就启用所有收费服务或上传长录音。

## 可追加给助手的任务

下面是在上方完整提示词之后追加的目标，不会扩大签名、凭据或设备操作授权：

**只想先看效果**

```text
先只跑Web预览，不下载官方安装包、不操作手机、不配置云服务。
请实际检查页面能访问，告诉我如何停止你启动的进程。
```

**Android 模型和导航**

```text
目标是Android官方扩展。先编译和校验APK，输出签名前检查结果。
我会在界面自己填模型和TinyFish Key。安装确认后，依次验证短问答、搜索、地图规划、模拟导航。
非Root已有用户验收，请继续记录我这台设备的签名、高德授权和镜片实测结果，不把历史成功当成本次成功。
```

**眼镜接入自己的知识库**

```text
手机基础对话通过后，再按我选择的平台文档接入自己的Codex知识库。
先问我允许读取哪个工作区和哪些数据源，默认只读并保留鉴权，不公开裸服务。
用无敏感内容的查询验证创建任务、完成、手机取回和镜片显示；不要启动自动批准。
```

“让Claude Code/Codex帮我搭建”与“眼镜通过Tools调用电脑Agent”是两件事。后者需要单独的bridge、网络与权限配置，各平台的实现/验收不同；不能因用Claude Code编译成功就标记Claude Code后端已接通。

## 最后应拿到什么

助手应给出：源码目录/版本、可重现命令、产物或预览地址、测试结果、用户配置项、尚未验收项和清理自己启动进程的方法。停在证书、兼容输入或物理确认上时应精确说明，不说“全部搞定”。有能力继续的本机步骤可以继续做，但不替用户确认镜片、签名或登录。

已有技能安装方式见 [AGENT_SKILL.md](AGENT_SKILL.md)。旧版技能曾只覆盖iOS；更新前先比较自己的改动，再按新分平台流程使用。
