# Norman IO：Hermes 电脑任务模式设计草案

状态：用户于 2026-09-12 批准设计并授权实施；代码、自动测试、真实 Hermes 文件/长任务/恢复/停止验收已完成，现有 HTTPS 桥接已切换，iPhone 已原位安装。用户回报验收显示“手机任务成功”，电脑文件内容核对一致；尚未分别确认手机与眼镜两处的显示细节。详见 `../../artifacts/hermes-tasks/review.md`。

## 用户目标与已确认选择

通过 IO 的文字或眼镜语音，像使用 WhatsApp 中的 Hermes 一样给电脑布置任务。
IO 使用独立会话，共享现有 Hermes 的模型、人设、长期记忆配置、技能和工具；不续写 WhatsApp 的对话。
“共享记忆”指复用同一记忆体系，不强行合并外部记忆服务按渠道隔离的数据。

第一版完成一个可验证的闭环：提交任务 → 电脑实际执行 → 查看进度或回答追问 → 取回结果 → 继续同一任务上下文。
文件操作、终端命令及已配置工具由现有 Hermes 执行；具体应用控制能力取决于电脑已有工具和系统权限。

## 改造前的限制与接口依据

- `agent-bridge/hermes_worker.py` 使用真实 AIAgent，但禁用了工具、MCP、插件及记忆写入。
- `agent-bridge/adapter.mjs` 每次启动受限 worker，最长运行 30 秒。
- `HermesConversationOperation` 在 25 秒后取消远端请求，语音生命周期结束也会触发取消。
- 当前只保存最近三轮内存上下文；重启 App 或保存配置会生成新会话 ID。
- 已知安装版本为 Hermes 0.18.2。核对其对应上游提交 `7b5ba205` 的公开源码，存在 TUI gateway 的会话创建、恢复、提交、状态、打断、追问和审批接口。
- 设计阶段先进行了源码兼容性检查；实施后已通过真实文件、长任务、重启恢复及前台进程停止验证。审批与追问使用隔离协议测试验证，未触发实际高风险命令或向他人发送消息。

## 接入方案比较

| 方案 | 优点 | 代价与判断 |
| --- | --- | --- |
| IO 桥接持有官方 TUI gateway 的 stdio 连接 | 原生会话、工具事件、追问及审批；可独立启动，不改 WhatsApp 平台配置 | 需要协议适配和长期任务状态管理。推荐。 |
| 启用官方 API Server，经 HTTP Runs API 调用 | 有标准 HTTP、任务状态和工具事件 | 需要安排现有 gateway 的配置与重启；安装版本的 Runs 实现没有最新版文档描述的完整请求去重和会话恢复行为。此次不选。 |

不采用仅删除当前 worker 工具限制的补丁：它无法解决长任务被取消、任务恢复、审批与完整工具上下文的问题。

## 推荐实现

### Mac 桥接与 Hermes

保留现有 Hermes HTTPS 地址（8443）及独立桥接令牌。桥接仍只监听 loopback，手机不直接访问原始 Hermes RPC。
由桥接管理独立的 Hermes gateway 进程，保持 stdio 连接；使用安装自带 Python 和官方入口，不修改 Hermes 安装源码或现有配置。

桥接只转发本功能所需的会话、任务、状态、打断、追问答复与审批 RPC；不提供任意 RPC、配置修改或登录管理入口。
启动时让 Hermes 自身加载现有配置。工具集合按现有 WhatsApp 的有效配置解析并在进程内传入，不能把 `all` 当作默认值；不把凭据内容返回手机或写入诊断。
若某个现有工具依赖 WhatsApp 的渠道上下文，应标记其在 IO 中不可用，不伪造 WhatsApp 会话身份。

为 IO 创建并持久保存专用 Hermes 会话 ID；App 重启、息屏、保存同一地址的配置不会自动创建新会话。
只恢复桥接自己登记的 IO 会话，不枚举或接管 WhatsApp、桌面或其他用户会话。
Hermes 按正常机制保存该会话的完整工具历史和记忆；桥接登记文件只保存必要的 ID、状态及去重信息。

每个 IO 会话同时执行一项任务。运行中普通新指令暂不自动排队；用户可回答 Hermes 的明确追问，或停止后再提交新任务。
接口进行版本和能力协商，旧的“仅对话”客户端不能无提示地获得电脑操作能力。

### 任务生命周期

客户端先持久保存请求 ID，再提交；服务端先登记该 ID，再启动任务。收到任务后立即返回回执，并持续归并官方事件。
状态至少区分：提交结果未知、执行中、等待用户、正在停止、已完成、失败、中断后需核对。
网络断开、手机息屏及眼镜结束收音只停止展示或监听，不自动停止已接受的电脑任务。
取消当前收音和停止电脑任务使用不同的操作入口。

移除对真实任务的 25/30 秒强制终止。连接与单次 HTTP 请求仍有短超时；超时显示状态未知，重新连接后核对原任务。
重复提交同一 ID 不再次启动。桥接或 Hermes 进程重启后不重放可能已执行的命令，也不承诺进程崩溃后自动续跑。
恢复时结合原任务登记和 Hermes 会话核对结果；无法确认时保留“需核对”，不能误报完成或停止。

“停止任务”调用 Hermes 的打断接口；收到请求只显示“正在停止”，确认执行退出后才显示“已停止”。已经产生的文件或其他副作用不会因停止而回滚。
任务结果以 Hermes 的终结事件和实际工具结果为依据；进度文字不能被当作完成结果。

### iPhone 与眼镜

会话页增加 Hermes 任务卡：当前状态、简短工具进度、结果正文、继续输入、停止按钮及必要的追问/确认。
把当前“仅对话”说明改成已验证的实际能力；连接检查同时验证桥接协议与 Hermes 就绪情况，不凭端口在线就称其可执行任务。

保留手机现有 DeepSeek / Hermes 选择。使用 Hermes 时，可先用“小雷小雷”或旋钮唤醒，再直接说任务，例如：
“读取 Turbo-IO 的 README，把运行步骤整理到 artifacts/io-task-demo/运行说明.md。”

眼镜显示简短接收回执和适合阅读的进度/结果，手机保留完整任务卡。
需要详细输入或审批时提示去手机处理。眼镜离线时不保证即时显示结果，重新进入 App 可核对任务。
本轮不再试写硬件唤醒词，也不把尚未实现的 Hey Norman 路由标为可用。

### 交互与权限

沿用 Hermes 对实际任务的工具与审批机制，不启用全局自动批准或“永久允许”。
手机上的确认卡绑定具体任务和请求，只提供本次允许或拒绝；语音转写、模型正文及重试不能代替用户点击批准。
追问答复与审批是不同事件。需要密码、sudo 或重新登录的操作提示回电脑处理，IO 不收集这些凭据。
界面说明任务将由 Mac 执行；有副作用的真实验收仅操作仓库中新建的测试目录，不向他人发送消息。

## 验收标准

- 同一配置下，IO 新会话可读取已有 Hermes 人设与记忆，调用实际可用工具，且不进入 WhatsApp 会话。
- 真实任务在仓库测试目录创建文件；第二轮根据第一轮上下文修改文件，检查落盘内容。
- 超过 30 秒的任务继续执行；退出收音或模拟客户端断开后，重新连接可查同一个任务。
- 重复提交、断网重连、丢失创建响应及进程重启都不自动重复执行有副作用的操作。
- 审批允许/拒绝、过期确认、明确停止、停止与完成竞态均有测试；不提前报告完成或停止。
- 用注入的协议/网络测试覆盖 Swift 状态转换；相关已有 Node、Python、Swift 测试通过。
- 真机上可由文字和眼镜语音提交任务，看到进度与结果；提交证据包括实际文件结果，而非仅模型自述。
