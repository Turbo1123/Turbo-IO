# RayNeo iO 原生跟读试验

## 目标与边界

Norman IO 目前只向眼镜提交 `scroll=2` 匀速提词。用户希望眼镜根据朗读进度移动稿件。RayNeo 官方产品说明列有智能跟随模式，但本仓库没有公开的模式枚举映射或智能跟读实机样本。因此先交付一个由用户主动选择、明确标记为试验的原生模式入口；只有真机观察到停读停滚、语速变化跟随，才能称为可用。

## 方案

- 保留现有匀速模式为默认值，速度 60–240 的控制不变。
- 新增“原生跟读试验”选项，选定后用当前已认证眼镜连接和现有文件通道发送短稿。准备请求尝试 `scroll=1`；这是未经验证的候选值，不作为协议事实写入通用枚举。每次准备只发送一次，不自动尝试其他值。
- 使用现有准备回应、文件传输回应、开始回应和进度回报显示事实；业务成功回应只能证明收到相应消息，不能证明镜片上的跟读效果。原始偏移不解释为语音识别结果。
- 试验期间可以暂停、恢复、退出。要回到匀速模式，先退出当前提词会话，再以匀速重新准备，避免同一会话中用未知状态切换。断连时保留现有“停止自动操作”行为。
- 试验说明提示眼镜可能使用麦克风。Norman IO 不新增手机录音、ASR 调用或音频保存。眼镜固件的识别位置、联网方式与费用未知；不要承诺离线或免费。业务 20 的 type 9 音频不解析、不保存、不当作成功回执。
- 保持稿件大小、本机存储、已认证设备、语音待命互斥与未确认时不得开始等现有限制。

## 实现与验证

将准备报文的模式选择提取为小型、可独立测试的构造逻辑；应用状态记录本轮请求的模式，以免界面选择在会话中途变化。界面提供两个模式与简短的试验说明；只有匀速模式显示速度调节。先写失败测试，再实现模式报文、默认兼容性和不支持值的保护；跑协议模块测试与 iOS 模拟器构建。最后用眼镜短稿验证：朗读、停顿、改变语速、退出并恢复匀速。没有真机结果前，界面始终标“试验”。

## 备选路线

如果 `scroll=1` 被拒绝或没有跟读效果，停止该候选值的试验，保留匀速入口。之后可分析已有真实协议回报，或另行设计手机 ASR 对稿匹配和滚动控制；后者有额外延迟、权限与潜在费用，不纳入本次实现。
